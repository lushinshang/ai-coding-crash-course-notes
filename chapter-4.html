4-01 你的起始 context

4-02 砍掉 context 肥肉
打開 request logger 逐項檢查 system prompt、工具定義與 MCP,親眼看清楚哪裡在浪費 token。

閱讀完整導讀 →
4-03 在 status line 顯示 context 用量
把 token 用量釘在畫面最下面,讓「context 偏執」變成隨時看得到的儀表板。
 ▸
閱讀完整導讀 →
4-04 探索程式庫
model 沒有記憶,每次開新 session 都要重新探路,探路品質決定後面一切的品質。
 ▸
閱讀完整導讀 →
4-05 ／teach skill
用 teach skill 把陌生 codebase 變成一堂為你量身打造的導覽課,而不是自己土法煉鋼亂逛。
 ▸
閱讀完整導讀 →
4-06 動手做一個功能
不用任何技巧、直接讓 agent 做一個課程評論功能,當作整章後續技巧的對照基準。
 ▸
閱讀完整導讀 →
4-07 plan mode 為什麼不好用
plan mode 只是把「急著生出成品」的毛病從程式碼搬到計畫文件,本質沒解決。
 ▸
閱讀完整導讀 →
4-08 Grill-Execute-Clear 循環
用 grill me skill 逼 agent 先把你盤問到雙方真正對齊,才准動手做,整章的核心工作流由此定名。
 ▸
閱讀完整導讀 →
4-09 compaction 壓縮
快滿的 context 不是硬撐也不是全清,而是把整個 session 壓成摘要、開新局繼續打。
 ▸
閱讀完整導讀 →
4-10 交接 handoff
compaction 出不了同一個 agent、同一個資料夾，這時候把 session 寫成一份可攜的 handoff.md，什麼人什麼工具都能接手。
 ▸
閱讀完整導讀 →
4-11 clear、compact、handoff 還是 subagent
一張決策樹，把清空、壓縮、交接、丟給 subagent 四條路配上判斷條件，收束前面幾堂學到的所有招式。
 ▸
閱讀完整導讀 →
4-12 自動 compaction
Harness 內建的自動壓縮能保底不爆 context，但在階段中途硬壓縮，往往換來風格跑掉、忘記需求的代價。
 ▸
閱讀完整導讀 →

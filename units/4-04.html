探索程式庫

model 沒有記憶,每次開新 session 都要重新探路,探路品質決定後面一切的品質。

模型什麼都不記得——這是所有限制裡最難繞過、影響最大的一個:每次開新 session,agent 都得靠探索重新找出它需要的資訊,而探索做得好不好,直接決定後面所有事情做得好不好。找不到該找的資訊,agent 大概率就做不出你要的東西。

打開 request logger 看 environment 這個欄位,會發現 agent 拿到的資訊其實出乎意料地少。它知道平台(作業系統)、工作目錄、在 Git repo 裡、shell 是 bash、自己的知識截止日期、目前分支、main 分支是什麼、Git user 是誰、Git status,還有最近一次 commit 訊息。但它完全沒有拿到目錄結構——沒有 `ls`,對檔案系統裡實際有什麼東西一無所知。agent 一開始的「認知」只有目錄名稱、一個模糊的環境描述、幾筆 commit 名稱,僅此而已。

換句話說,agent 打開一個陌生 codebase 的處境,跟一個第一次接手這個專案的人差不了多少——都得靠自己動手去問、去讀,才能拼出這個專案到底在做什麼。清空 context,直接問它「這個專案的技術棧是什麼、用途是什麼」,然後觀察它怎麼回應:是自己一個一個讀檔案,還是會生出 subagent 去做這件事?這個觀察點很重要,因為後面會反覆用「探索方式消耗多少 context」當判斷依據。

這是整章從「清理環境」轉向「開始做事」的轉折點:前面幾堂都在打掃地基,這裡才第一次真的跟 agent 互動、觀察它面對一個陌生 codebase 時怎麼行動——也替後面把這個摸索過程包裝成系統化教學互動的內容鋪路。

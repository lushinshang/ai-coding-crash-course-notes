無狀態

模型什麼都不記得，記憶其實活在 harness 跟環境裡——這決定了「AI 的記憶系統」該怎麼設計。

模型不是「讀取記憶」，是每一次都被重新告知一切。這句話拆穿了一個容易被誤會的直覺：session 裡累積的 context，看起來像是模型「記得」之前發生過的事，但整個 session 的狀態其實存在 harness 這一層，模型本身完全無狀態。每一次 model provider request，harness 都要把之前發生過的一切重新打包、完整送過去，因為模型自己什麼都不記得。跟非決定性放在一起看會更清楚：模型不只每次答案可能不同，它連上一秒鐘發生過什麼都不知道，全部要靠外部餵給它。

很多人把這種無狀態視為缺陷，於是拼命想幫 agent 裝上「記憶系統」，讓它記得你、隨時間變聰明。但這個問題其實該拆成三層看：模型完全無狀態；harness 是有狀態的，但只在同一個 session 內有效，一旦清空 session，harness 這層記憶也跟著歸零；只有環境——也就是檔案系統——是真正持久的，把東西寫進檔案，就算 session 清空了，那個檔案還在。真正能撐起長期記憶的，從來不是模型，也不完全是 harness，而是環境本身。

Pi 的創辦人 Mario Zechner 有句話說得很直白：「我常被問用什麼記憶系統，我的答案一直是——我的程式碼庫就是我的記憶系統。」這個立場值得認同：預設情況下盡量保持無狀態，把重要的東西存進程式碼庫裡，理由很單純——這樣做比較簡單，而且實測下來效果更好，對那些試圖把記憶系統直接掛在 agent 本體上的做法反而該抱持懷疑。與其把資源花在讓模型本身變得更聰明、更有記憶，不如把力氣投資在環境設計上——這件事完全掌握得住，而且好處會一直留著，不會隨模型換代而消失。

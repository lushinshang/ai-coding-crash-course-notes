第6章 把功能出貨 · 6-07

改道：目標變了怎麼辦

半途發現方向錯了，刪掉未做的 ticket、回頭改 spec、重新產生新一批 ticket 就好。

這堂課處理一個很現實的情境：spec 定了、ticket 也拆好了，做到一半——可能兩張票做完了——你忽然發現，糟了，這個方向根本不對。這時候該怎麼辦？

Matt 給的答案建立在一個關鍵前提上：ticket 是可拋棄的。如果已經做了前兩張，後面還沒動的直接刪掉就好，不用有心理負擔。真正要回頭處理的是 spec，而 spec 是可編輯的——你可以就當下的狀況重新開一輪 grilling session，跟 agent 對齊「我們現在在哪裡、原本的方向為什麼不滿意」，改完 spec 之後，再重新跑一次生成 ticket 的流程。新產生的這批 ticket 範圍可能會比原本略有增減，但重點是你找到了一條從「現在的位置」通往「新目的地」的路徑，而不是從頭砍掉重練。

整套流程可以濃縮成一句口訣：發現目的地要換 → 刪掉還沒做的 ticket、但留著 spec → 用 grill 重新調整 spec（通常開新 session 做）→ 對 spec 滿意後重新生成 ticket → 從現在的進度繼續實作。

這堂課同時也解釋了 6-03、6-04 那套「spec 和 ticket 分成兩份文件」的設計動機——如果兩者混在同一份文件裡，遇到要改道的狀況會變得很混亂，分開存放才能讓 spec 穩穩當「目的地」，而 ticket 徹底可拋棄、隨時可以重新產生。這也是整章「從 issue 到出貨」流程能保有彈性、不怕中途翻盤的關鍵設計。

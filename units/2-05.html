聰明區與笨蛋區

token 數量越多，關係數量呈平方成長，這是整章最硬核也最實用的一堂——你的 agent 有保鮮期。
18K
上一堂那份 log 的實際 token 數
10億+
10萬 token 要追蹤的關係數
15萬 token
目前公認的笨蛋區警戒線

上一堂看到的那份 log，攤開來一大片，看起來嚇人，但實際上只佔了 18K token——模型的上限是一百萬，等於你手上這份「已經覺得很多」的東西，連容量的百分之二都不到。這個對比本身就很說明問題：容量從來不是瓶頸，會出問題的地方，是容量被用滿之後模型還能不能好好想事情。

答案是不能，而且原因不是玄學，是算術。丟一個字給模型，它輕鬆，沒有任何東西要對照；丟第二個字，情況變了——它得記住兩個字各自是什麼，還得判斷這兩個字之間有多相關，於是兩個字背後其實是三件事在被追蹤：第一個字、第二個字、還有它們的關係。加到第三個字，關係數不是加一，是跳到三組；四個字，六組；五個字，十組。每多一個字，要追蹤的關係是用平方的速度在漲，不是跟字數同步往上爬。換算到真實的量級更明顯：一千個 token，背後對應大約一百萬組要顧的關係；一萬個 token，一億組；十萬個 token，逼近一百億組。這套負責追蹤字與字之間關聯的機制，就是 attention——而當要顧的關係多到一個地步，它沒辦法每一組都認真看。

一支球隊加進聯盟，聽起來只是多一個名字，但賽程表要排的場次瞬間暴增——這正是關係數字爆炸的樣子，也正是 attention 在大量 token 湧入時面對的處境：所有字都在搶著被注意到，模型分不出誰才是真正重要的那幾個，這就是注意力退化。

於是 context window 裡分成兩個區——不是切得整整齊齊的兩塊，是一條緩慢下滑的坡度。前段是聰明區，模型還撐得住複雜的規劃、寫得出結構完整的東西；往後滑，進入笨蛋區，它還能做，但只剩下寫檔案、關 issue 這種粗活，你不會再從這裡拿到它的最佳表現。目前公認的警戒線大概落在十五萬 token——這數字前一版課程錄的時候還在十到十二萬，隨模型變強持續往後挪，但笨蛋區這個現象本身不會消失，它是這套機制的數學本質，不是某一版模型的暫時缺陷。

那一百萬 token 的規格數字，到底是講給誰聽的？一部分確實是好看的行銷語言，但另一部分是誠實的：有些任務，例如在大量文本裡撈一段特定內容，本來就不需要聰明區，只要撈得到就好。真正要規劃、要寫扎實軟體的人，一百萬這個數字幾乎沒有意義，該盯著的只有那條十五萬的警戒線——而且最好在真的滑進笨蛋區之前就開始緊張，開始想怎麼收尾、怎麼交接，而不是等到症狀已經很明顯才反應。這條警戒線之後會反覆出現：幻覺變嚴重、需要靠 subagent 分工，追根究柢都是同一件事——想辦法把工作盡量留在聰明區裡完成。

一輪對話與模型供應商請求

打開 request logger 看穿一次對話背後，harness 跟雲端模型之間真正在傳什麼。

打一句「hello」，收到一句「hello, what would you like to work on today?」——使用者眼中極簡的一問一答，翻開 log 檔看到的卻是一份塞滿系統提示、工具定義、對話歷史的巨大請求，最後才輪到那句簡短的回覆。這個懸殊的對比，正是這堂課要讓你親眼看見的東西：把 request logger 接上本地紀錄伺服器，每一次跟模型的往來就不再消失在黑盒子裡。

這個「本地 harness 打包一切送到雲端模型、拿回一小段文字」的往返，有個明確名字：model provider request（模型供應商請求）。即使用的是 Ollama 這種本地跑模型的方案，這個概念依然成立，只是供應商剛好跟 agent 擠在同一台機器上。真正關鍵的一段示範是叫 agent 寫一個檔案：這時候 log 裡出現的不是直接的文字回覆，是一段 JSON——「我要呼叫 write 工具，參數是這個檔案路徑跟這些內容」。harness 收到這段 JSON 後自己去執行寫檔案的動作，再把「檔案建立成功」這個結果包成新的請求送回模型，模型才據此產生「完成了，我在根目錄建立了 compliments.md」這句回覆。

這一來一回——訊息、工具呼叫、工具結果、新訊息——被稱為一個 turn（輪）。一個 turn 可以拖上好幾個小時，內含成百上千次的 model provider request，畫面上那句「agent 正在思考」，往往是無數次雲端往返疊出來的結果，不是單一次請求在慢慢運算。這堂課建立的詞彙表——model provider request、tool call、tool result、turn——不是為了掉書袋，是後面所有討論 context、成本、效能優化時，唯一能拿來精確描述問題的最小單位。沒有這套語言，很難跟人討論「為什麼這次對話變貴了」或「為什麼模型突然變笨」，因為那些現象背後，說到底都是這幾個詞彙組合出來的結果。

用這個 skill 寫出好 spec

spec 是目的地文件，用 to-spec skill 把已經聊過的內容濃縮成一份完整規格。

這堂課銜接的是前面已經建立好的概念：spec 是一份目的地文件，能幫你在多個 session 之間管理 context，也給了你一個明確瞄準的方向。既然知道為什麼要有 spec，接下來自然的問題就是怎麼生出來——答案是用 `npm run reset` 拉進來的 to-spec skill。

這個 skill 的設計哲學值得注意：它不會反過來質問你一堆問題，而是預設「已經有過一輪充分的討論」，直接把當下對話裡累積的理解和程式碼探索結果，濃縮成一份 spec。也就是說，前面已經有過的「grilling session」（跟 AI 對齊想法的討論過程）才是原料，to-spec 只是把原料萃取、定型。這也點出整章的五步驟骨架：先 grill 對齊想法，再產出 spec 定目的地，再拆成 ticket，一張張實作，最後回頭跟 spec 對照做審查。

spec 本身用一個固定模板產生，內容包含問題陳述、解決方案、以及一批 user story——這是很經典的軟體開發手法，目的是讓拿到這份文件的實作端 agent，能得到足夠紮實的資訊去把工作做完，不需要再回頭問你太多細節。這一步是整條流程裡承先啟後的關鍵：往前銜接的是已經發生過的討論，往後銜接的是 6-04 要教的 ticket 拆解。

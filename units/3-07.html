權限設定

從逐次核准、settings.json 到 auto mode 的 LLM 分類器,是把「風險換效率」調到自己舒服刻度的機制。
3
核准選項:這次允許、永遠允許、拒絕
4
權限模式:manual / accept edits / plan / auto

把 Claude 的權限開到無限大,像不少人做的那樣,等於是在賭它不會手滑把整個檔案系統刪掉——跟 agent 合作永遠要衡量風險與報酬,尤其是你願意放給它多少權力。Claude Code 的解法是一套很細緻的權限模型,預設狀態非常保守:跑 `echo hello` 這種絕對安全的指令會直接放行,但換成跑 type check,系統立刻跳出確認框,列出確切要執行的指令、想這麼做的理由,並給出三個選項——這次允許、以後在這個專案裡看到同樣指令都自動允許、或拒絕。拒絕的時候還能按 Tab 補充理由,比如改口要求換一個指令,系統會拿著新指令再問一次。

這些「以後都允許」的選擇不是隨口說說,會被實際寫進 `.claude/settings.local.json` 底下的 `permissions.allow` 陣列,而且這份設定可以直接手動編輯——提前把知道會反覆用到的指令列進去,或者用萬用字元讓某一類指令全部自動放行。反過來,`deny` 陣列能明確擋掉危險動作,像用萬用字元直接封殺所有 `git push`,不用每次手動攔。這套機制不只管 bash 指令,web 搜尋跟網頁抓取同樣要走這個核准流程,答應之後規則一樣會被寫進去。

`settings.local.json` 這個檔名裡的「local」不是隨便取的——它預設被 `.gitignore` 排除,只對你個人生效。想把這組規則變成整個團隊共用的預設值,做法很簡單:把檔名改成 `settings.json`,這樣就能進版本控制、跟著 repo 一起分享,任何人第一次在這個專案跑 `claude`,都會自動套用同一套權限規則,不必每個人重新手動核准一輪,對新加入專案的人特別省事。

再往上一層是 auto mode。用 Shift+Tab 可以在 manual(逐次核准)、accept edits(自動接受編輯)、plan mode、auto mode 之間切換,auto mode 用一個 LLM 分類器(推測是 Haiku 量級)在動作執行前先評估指令安不安全,安全就直接放行不用你介入。代價是會多花一點 token 跟時間讓分類器判斷,而且分類器不是完美的——有時候資料庫遷移這種危險動作被放行,建立 GitHub issue 這種正常動作反而偶爾被卡住。即便如此,整體抓得剛好在可接受的那一側:真正危險的操作幾乎都會被擋下,又不太會把使用額度衝高太多。更重要的是 `settings.json` 跟 auto mode 不是互斥的,harness 會先檢查 settings 裡有沒有現成規則,沒有才丟給分類器判斷——把常用指令寫進 settings.json,等於幫 auto mode 分流減負。這個預設值可以到 `/config` 裡的「default permission mode」設定起來,固定用 auto mode 之後,權限彈窗自然就很少打斷你的節奏。

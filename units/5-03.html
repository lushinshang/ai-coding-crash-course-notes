什麼是 Agent Skills

doc + pointer 無法跨專案攜帶,Agent Skills 把這個模式打包成可分享的標準格式。

上一集做出來的 doc + pointer 組合雖然解決了 context load 的問題，但 Matt 點出它有個明顯的天花板：整套東西完全綁死在這個 repo 裡，你沒辦法把它包一包直接送給同事，也沒辦法帶去下一個專案，只能手動複製貼上。Agent Skills 就是為了解決這個「可攜性」問題而生的標準化包裝。

一個 skill 本質上就是「同一套指標模式，但打包成標準化的自包含資料夾」——裡面有個 SKILL.md，扮演的角色跟之前的 doc 一模一樣，但多了 name 和 description 兩個欄位，這兩者本身就是那個 context pointer：harness 平常只把 name/description 放進 context window，讓 agent 自己判斷「這個描述符不符合現在的任務」，符合才把 SKILL.md 的完整內容拉進來。Matt 用自己寫的「writing for agents」skill 當例子——description 寫著「use when creating or editing skills or modifying agents.md or claude.md」，就是一句典型的判斷觸發條件的話。更進一步，skill 資料夾裡還能塞其他檔案，形成多層指標：SKILL.md 裡又可以再指向資料夾裡的 reference.md（例如他自己的 skill 裡就有一份只在「你現在正在寫 skill」這個情境下才需要用到的 skill mechanics 檔案），可以做到相當深的資訊分層，卻完全不需要一次全部塞進 context。

這集另外一個重點是 model-invoked 和 user-invoked 的差別。預設情況下 skill 是 model invoked，description 會進 context window 讓 agent 自己判斷要不要拉；但你也可以設 disable model invocation: true，讓這個 skill 的 description 完全不進 context window，harness 甚至不知道它存在，只有使用者自己主動叫它才會跑（他舉了 handoff 這個 skill 當範例）。這形成一個取捨：model-invoked skill 越多，context load 越高；user-invoked skill 越多，則是「認知負擔」越高——因為使用者自己要記得有這些 skill、什麼時候該手動叫。Matt 坦承自己寫的 skill 大多是 user-invoked，因為免費（不佔 context）這件事對他來說很有吸引力。他也提到 Agent Skills 是在 agentskills.io 定義的開放標準，代表一個 skill 寫一次可以在所有支援這套標準的 harness 上通用，這也是為什麼它比單純的 doc + pointer 更值得投資。這集是純講解，為 5-04 的動手實作暖身。

安裝 Claude Code

裝好 CLI、選對模型與 effort、打一聲招呼確認能通，agent 才算真正上線。
1M tokens
Opus 5 上下文視窗
Medium
課程錄製時用的預設 effort

前面兩堂課把舞台搭好了——專案裝好、終端機開好，唯獨少了真正會動手做事的那個角色。裝 CLI 這段本身沒什麼好講的：依平台複製對應指令、貼進終端機、跑起來、對「是否信任這個工作區」按下同意、登入時選訂閱選項而不是 API key。真正值得記住的是這段操作附帶的一句提醒——同一套安裝邏輯，換成 Codex 或其他 agent 一樣適用，這句話呼應的是第一堂課就立下的原則：工具是替換品，方法才是核心，這門課不是在教你記住某個 CLI 的操作細節。

選模型這一步才是真正該停下來想的地方。用 `/model` 指令叫出選單，建議做法是直接選訂閱方案自帶的預設模型——就這麼簡單，不用糾結該選哪一個型號。示範時選的是配了一百萬 token 上下文視窗的 Opus 5，但這裡藏著一個容易被忽略的細節：effort 等級可以用左右鍵調整，而錄這門課的當下用的其實是 medium effort 的 4.8，因為 Opus 5 那時候都還沒問世。這段話本身就是一個示範——課程內容不會因為模型版本更新而失效，重點是「用你方案裡的預設中階模型」這個選擇邏輯，不是死記某個型號名稱，型號會換，這個判斷原則不會換。

最後一步是打一聲招呼，收到回應就代表設定成功。這個動作看起來像儀式，實際上是整條安裝鏈路的最終驗收——CLI 裝對了、登入的帳號權限夠、模型選對了、網路連得通，四件事只要有一件沒到位，這聲招呼就打不通。看到回應跳出來的那一刻，才算真正踏進這門課要教的核心內容；在此之前的一切，都只是把舞台搭好而已。

Grill-Execute-Clear 循環

用 grill me skill 逼 agent 先把你盤問到雙方真正對齊,才准動手做,整章的核心工作流由此定名。

大部分 agent 拿到一句模糊的需求就會立刻動手,因為「生出東西」是它的預設反射動作——先探索 codebase,再開始寫程式,中間完全沒有跟人對齊的步驟。grill me 這個 skill 做的事情正好相反:它把 agent 的第一個動作從「執行」換成「審問」。skill 裡最關鍵的第一句話寫得很直白:不斷盤問使用者直到雙方達成共同理解,而且明確禁止在達成共識前動手。這一句禁令才是整個機制的核心,它把 agent 原本急著產出東西的傾向硬生生按住。

grill 階段不是隨便問幾個問題就結束,skill 裡定義了明確的終止條件:設計樹上每一個分支都被走訪過,沒有任何東西被默默假設掉,才算完成。這代表使用者一開始丟出去的 prompt 可以非常鬆散——像是「我們要做課程留言功能,讓學生跟講師都能在課程頁面留言」這種程度就夠了,不需要一次講清楚所有細節。接下來的責任轉移到 agent 身上:它得主動把每一個沒講清楚的分支挖出來問,直到雙方對要蓋的東西有完全一致的理解為止。這跟平常「你講需求、它就照做」的互動完全不同,agent 在這裡被要求先確認理解是否對齊,而不是先交出成果。

理解達成共識之後,循環才進入 execute 階段——這時候才真正開始實作,而且是一路做到底,不再中途停下來確認。呼叫方式依 harness 而不同,在 Claude Code 裡是打斜線加上 grill me,流程一致:先用一句鬆散的話啟動討論,被 agent 問到底,再放手讓它執行。這個順序本身就是設計重點——先把設計空間問窮盡,再一次做完,而不是邊做邊猜、邊猜邊改。

第三階段是 clear:每完成一輪,再回到 grill 開始下一個功能。這個循環之所以叫「循環」,是因為它預期會被反覆使用在一個又一個獨立任務上——grill 定義問題邊界、execute 執行到底、clear 把 context 歸零避免上一輪的假設污染下一輪。清空的動作看似瑣碎,實際上是在保護 grill 階段建立的那份共識不被舊 context 稀釋或混淆。

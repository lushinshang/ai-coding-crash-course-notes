第2章 核心概念 · 2-11

subagent

把探索工作外包給另一個 agent，用它的 token 換自己的聰明區——這是笨蛋區問題的第一個系統性解法。

context 塞得越滿，模型越笨，而且越貴，理想狀況下每個階段都該盡量精簡。但如果探索階段做得太省，蒐集到的資訊不夠完整，接下來的實作階段就會因為資訊品質不好而跟著出錯——這變成一個死結：想省 token，卻又不敢省，因為省下來的代價會轉嫁到後面。

解法是把探索這件事外包給另一個 agent。主 agent 不必自己在 context 裡塞滿探索過程中翻閱的每一個檔案、每一段程式碼，而是叫另一個子 agent 去做這件深度探索的工作，那個 subagent 可以在自己獨立的 context 裡盡情花費 token 去深挖程式碼庫，最後只把整理過的結論、摘要傳回主 agent。這就像資深工程師交辦一個 junior 工程師「幫我研究一下這個，回報結果給我就好」——junior 花的力氣不會佔用資深工程師自己的 context 額度。

這個機制還能再往下延伸：主 agent（也就是 orchestrator，協調者）可以同時並行派出多個 subagent，各自負責不同的研究任務，就像兩個 junior 工程師同時分頭調查，最後各自回報。subagent 甚至可以被指定用不同的系統提示、不同的模型、不同的 effort 等級去執行，而且部分 harness 還允許 subagent 再往下衍生出自己的 subagent，雖然不是每個 harness 都支援多層。subagent 不是打折版的助手，它可以跟主 agent 一樣強大，差別只在於它被賦予的任務範圍，以及產出的資訊最終要怎麼被摘要、被送回主線。

這個收尾巧妙地把整章串成一條線：從認識 agent 的四個零件開始，中間拆解了非決定性、context、聰明區笨蛋區、無狀態、成本、幻覺、effort、選模型，最後停在 subagent——一個把前面所有限制條件都納入考量後，自然浮現出來的架構性解法。理解了這條推導鏈，subagent 不是一個炫技功能，而是這整套系統設計邏輯下，幾乎必然會出現的答案。

建立練習專案

git clone、npm install、資料庫 migrate 與 seed，一路把 Cadence 跑起來的完整儀式。
10.5萬/週
Sancastle 套件下載量
5 步驟
clone → install → migrate → seed → run

選編輯器這件事，答案出乎意料地無趣——不是因為哪一套最強，是因為免費、跨平台、夠親民，而且內建終端機。這個內建終端機的條件才是真正的關鍵：這門課大部分時間都在終端機裡跟 agent 對話，編輯器本身反而是配角。如果手上已經有慣用的工具，只要能開終端機、能看程式碼，直接繼續用也沒問題——這種不執著品牌的態度，貫穿了整堂課挑工具的邏輯。

真正的儀式從終端機開始：先確認 git 裝好，把課程的 repo clone 下來，再確認 Node.js 裝的是 LTS（長期支援版），不是 Current 那個號稱最新最潮但穩定性沒保證的版本。裝好之後跑 `npm install`，把一整批套件拉進 `node_modules` 資料夾。這一步經常被當成無聊的等待畫面直接跳過，但值得多看一眼——裡面裝的是別人發布到 npm 上的套件，其中一個叫 Sancastle 的套件，一週的下載次數是十萬五千次。這個數字不是拿來炫耀的花絮，是在建立一個之後會用到的概念：專案依賴的每一個套件，背後都是一個被廣泛使用、有真實下載量的獨立作品，不是憑空冒出來的黑盒子。

裝完套件，下一步是把資料庫生出來——先跑 migrate 建立空的資料表結構，再跑 seed 灌進假資料。跑起來之後看到的 Cadence，就是接下來整門課要動刀的對象：一個功能齊全、有賣課程、上課、測驗的真實應用。畫面下方藏著一個容易被忽略但後面會一直用到的功能——切換登入身份的 dev UI。切到 Emma Wilson，就能看到她已經買了 TypeScript 和 Node.js 兩門課；這不是順手帶過的小玩具，是接下來所有「這個角色看到的畫面對不對」測試的入口，沒有它，每次驗證都得手動改資料庫，效率會差一大截。

這堂課沒有太多概念要消化，但它是後面所有動手練習的地基。看到假資料成功顯示在畫面上，就代表環境完全就緒——可以正式開始跟 agent 打交道了。

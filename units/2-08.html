第2章 核心概念 · 2-08

幻覺

幻覺分兩種——一種是模型真的不知道，一種是明明給了答案它卻不理你，對策完全不同。

進了笨蛋區之後，agent 具體會做出什麼蠢事？最危險的答案是幻覺（hallucination）——模型自信滿滿地講出錯的東西。在寫程式的情境裡，這造成的傷害非常直接：產出根本跑不起來的程式碼、把產品方向帶偏、甚至推薦一個早就不安全的 API。

真正值錢的是把幻覺拆成兩種完全不同的成因。第一種叫 factuality（事實性）幻覺：模型講出不存在的函式、錯誤的 API 簽名、捏造的引用文獻。這種幻覺的根源是 parametric knowledge（參數化知識）不足——模型的知識是在訓練當下被壓縮進幾十億個數字裡的，就像一張極高解析度的照片被壓成很小的檔案，細節必然會流失；而且這些知識有截止日期，訓練之後發生的事、新出的函式庫和 API，模型完全不知道。有個真實案例很能說明問題：問 Opus 4.8「不要搜尋，憑你所知回答，X 的 API 多貴」，模型很篤定地回了一套過時的價格分級，還加註「可能已過時」；但改口叫模型去搜尋查證，才發現它記的價格早在今年 2 月就變了——模型對舊資訊的記憶也只是模糊的印象，不是精確的資料庫查詢。

第二種叫 faithfulness（忠實性）幻覺：就算已經把正確資訊親手放進 context 裡，模型還是可能忽略它、偏離它，或用一種很奇怪的方式曲解它。這正是笨蛋區最惡劣的地方——因為注意力退化，context 裡塞太多東西時，模型分不出哪些才是真正重要的資訊，即使答案就白紙黑字寫在眼前，也未必抓得到。有個很實用的判斷樹：碰到幻覺時，先問「這個資訊有沒有在 context window 裡」——沒有，那是事實性問題，解法是把正確的資訊載入 context（永遠不要信任沒有來源的 LLM，一定要讓模型基於有出處的資料回答）；如果資訊明明就在 context 裡，那就是忠實性問題，多半意味著該退出笨蛋區、清空 context，讓注意力退化降下來，模型才能喘口氣。

值得注意的是，就算人在聰明區，忠實性幻覺也不會完全歸零——因為非決定性意味著模型永遠有非零機率選到一個奇怪的走向。不指望這個問題會被廠商徹底解決，但理解這套「先分類、再對症下藥」的邏輯，會讓接下來整門課碰到奇怪輸出時，第一反應不是慌，而是先判斷這是哪一種幻覺。

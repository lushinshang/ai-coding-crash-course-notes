第3章 認識 Claude Code · 3-06

執行 bash 指令

三條路線分別對應共享資訊、持續監控、完全隔離——決定 Claude 能不能看見指令結果。

能不能執行 bash 指令,是「被動寫程式碼的工具」跟「真正能自己找回饋迴圈、跟專案互動的 agent」之間的分界線。沒有這個能力,Claude 只能憑猜測生成程式碼,寫完就結束;有了它,Claude 能自己讀 `package.json` 找出 dev server 指令、自己執行、自己看結果修正,一整輪「寫→跑→看錯誤→改」的迴圈不需要你插手傳話。

操作上很簡單:在輸入框打一個驚嘆號 `!` 就進入 bash 模式,接下來打的任何東西都會被當成 shell 指令直接執行,結果直接放進 Claude 的 context。跑一次 `npm run type check`,如果環境沒先裝好依賴,會冒出一堆錯誤——但這些錯誤同樣進到 Claude 的視野裡,不需要你複製貼上,它自己就能看出某個套件雖然寫在 `package.json` 裡卻沒真的安裝,直接建議跑 `npm install` 解決。這是 bash 模式最實用的場景:手動跑一個會出錯的指令,把錯誤直接餵給 Claude,省掉中間傳話這一步。

但 bash 模式處理不了「跑起來不會結束」的指令,比如 dev server。這時候要先在 bash 模式裡跑起來,趁它還在跑的時候按 Ctrl+B 把它丟到背景執行——畫面上會出現一則背景化的提示,輸出內容寫進本機檔案,狀態列多一個背景任務的入口。用方向鍵移到那個任務按 enter,就能檢視這個背景 shell 實際在做什麼、按 X 直接停掉它、或按左鍵退回主畫面。這對除錯 dev server 問題特別好用:Claude 能自己看 log、自己送 curl 請求驗證、自己讀懂輸出,整個除錯迴圈完全不需要你在中間傳話。

最後一個工具方向完全相反——如果想跑一個指令但完全不想讓 Claude 看到結果,又要保留它目前的對話狀態不被打斷,就按 Ctrl+Z 把 Claude Code 整個掛起。終端機回到普通 shell,可以做任何事,Claude 完全看不到;做完之後打 `fg` 就能把它原封不動叫回來。三條路線各自對應一種協作意圖:想讓 Claude 看到結果就用 `!` 進 bash 模式,要長駐執行就 Ctrl+B 丟背景,完全不想讓它看見就 Ctrl+Z 掛起——分別是共享資訊、持續監控、完全隔離。

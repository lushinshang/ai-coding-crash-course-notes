第4章 基本功 · 4-01

你的起始 context

打第一個字之前,harness 可能已經替你塞了 23K token 的雜訊,而你完全沒發現。
23K
什麼都還沒做,harness 預設就佔用的 token 數
6.6K
清掉不必要設定後的 token 數
17K
純靠設定檔取捨省下的 token 數

打開一個全新對話,還沒送出任何訊息,context window 就已經不是空的了——系統提示、內建 skills、專案資訊、甚至遠端載入的 MCP 工具,全部在你打字之前就佔好位置。多數人從來不會去檢查這個起跑點乾不乾淨,預設它就是零,但這個假設本身就是問題:如果起點就帶著一堆不必要的 token,後面再怎麼精算對話節奏、再怎麼抓 compaction 時機,都只是在一個已經髒掉的底子上修修補補。

做法很直接:把 `.claude` 資料夾裡的 `settings.json` 和 skills 都先改名備份,等於把設定重置成預設值,再跑 `/context` 看一眼。結果通常會讓人意外——什麼都還沒做,只打了八個字元的 `/context` 指令,畫面上就已經有 23K token,來源是內建 skills、內建 project 資訊,還有一大票從外部載入的 MCP 工具。把備份的個人設定加回去再跑一次,數字掉到只剩 6.6K——單純靠設定檔的取捨,就砍掉了 17K token,而這 17K 從頭到尾都不是你需要的東西。

這裡刻意把「效率」和「品質」分開講:清掉這些雜訊不是為了省幾毛錢的 API 費用,而是為了把 context window 裡還能維持高品質輸出的那段空間——也就是前面章節提過的「smart zone」——留給真正有用的內容。塞得越滿,能拿到的智慧就越稀釋,這是接下來整章的第一塊地基:後面所有談 context 管理、grill-execute-clear、compaction 的內容,前提都是你已經先把起跑點清乾淨了。檢查一次自己實際在用的 harness 帶了什麼,通常會比想像中更讓人吃驚,尤其是從來沒去看過的人。

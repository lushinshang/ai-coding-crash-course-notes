這門課要帶你去哪

兩百萬星星專案的作者濃縮兩年 AI 編碼經驗成五步驟系統，重點不是換模型，是換你自己。

這門課結束時，你會變得很能打，但不是因為你的模型變強了。這句話聽起來像客套話，但其實是整門課的立論基礎——課程作者把自己過去兩年跟 AI agent 搏鬥的經驗，濃縮成一套五步驟系統：先逼問清楚需求（grill），寫成一份規格（spec），把規格拆成一張張工單（ticket），動手實作，最後做審查。這五步在他這兩年不斷換模型、換工具的過程中從沒變過，這也是他敢開這門課的底氣——如果連他自己都還在找答案，這課根本開不起來。

有意思的是，這套方法論刻意不綁定任何特定 agent。它的判準只有一個：能不能在終端機裡跑、能不能讀 skills。這個門檻低到幾乎涵蓋市面上所有主流 agent——Claude Code、Codex、OpenCode、GitHub Copilot，隨便換一個都能用同一套流程。所有教學內容也是用 skills 的形式交付，理論上你學完可以直接把這批 skills 搬到任何一個 agent 上用。這個設計決定背後藏著一個判斷：agent 這個東西汰換速度太快了，押注在某一個工具的操作細節上，賭注下得太大；真正值得投資的是背後那套不隨工具更迭而過時的方法論。示範用的 agent 選了 Claude Code，理由很直白——這是作者自己每天在用的主力工具，也剛好是目前最多人用的一款，但一旦進入課程核心，幾乎不會再特別談論它。

支撐這個判斷的，是作者自己維護的一個 skills 專案——星數剛跨過二十萬顆，擠進史上星數最多的 GitHub 專案前二十名，下載次數超過一千三百萬次。這個數字不是拿來炫耀的，它其實是在回答一個隱藏的問題：如果方法論真的能脫離特定工具獨立存在，那它應該能被大規模驗證過，而不只是一個人的個別心得。

練習場是一個叫 Cadence 的 TypeScript/Node 應用，功能成熟到有真實的線上課程平台該有的東西——買課、上課、測驗。整門課會讓你在這個真實的軟體開發生命週期裡，跟 agent 一起把一個又一個功能真正做出來，走的是作者過去十年一直在用、後來發現跟 agent 搭配起來特別有效的那套流程，不是憑空設計出來的教學案例。

進入門檻低得幾乎沒有障礙：看得懂程式碼、會用終端機。看得懂程式碼不代表要會寫，能大致理解「這段在幹嘛」就夠了；會用終端機也只是要求你認得 `cd`、`ls` 這種基本指令，知道自己在裡面做什麼。門檻這麼低，跟結尾那句承諾放在一起看才有意思：上完課，你能出更大量、更高品質的成果——但推動這件事的不是模型變聰明，是你自己學會怎麼驅動 agent。這套方法論對 context 的負擔極輕，它要的不是更貴的算力，是你腦子裡多一點理解。而這，正是整門課想做的事。

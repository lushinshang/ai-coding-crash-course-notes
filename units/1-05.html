練習怎麼跑

git checkout -b dev 開分支，npm run reset 穿梭時間點，配合 cherry-pick 保留自己的改動不被沖掉。
3 個指令
reset／cherry-pick／pull

遠距教學有一個從沒被真正解決過的問題：老師在畫面上示範完一個功能，你怎麼確定自己電腦上的程式碼，跟老師剛剛講的是同一個狀態？大部分課程的答案是「請自行對照」，但這門課的答案是一套自己寫的工具鏈。第一步很簡單，建一個叫 dev 的分支當練習場，這個分支之後會被隨意弄髒、隨意實驗，不會動到 main 分毫。

真正的核心是 `npm run reset`。每一堂課的每個階段都對應一個或多個 git commit，跑這個指令會列出一長串可以「跳」過去的時間點，選一個就能把本機狀態瞬間對齊到影片拍攝當下的程式碼樣貌。有個帶點自嘲的示範很能說明這個機制多精準：`package.json` 裡課程平台的描述打錯字，寫成「awesome horse platform」而不是「awesome course platform」，跑 reset 選到對應的 commit，錯字瞬間被修正——一個 bug 級的打字失誤，反而成了展示時間旅行精準度最好的教材。

但 reset 有個代價：它會把你自己動手加的東西一併洗掉。示範裡加了一個 foo bar 的 npm script、commit 下去，跑 reset，foo bar 直接消失，一點痕跡都不留。對還在摸索、捨不得自己改動被洗掉的人，另外準備了 `npm run cherry-pick`——概念上就是 git cherry-pick，把某個歷史 commit 疊加到目前分支上，而不是把整條分支輾平重來。但這裡有個誠實的但書：如果對 git 的 cherry-pick 和衝突解決不熟，乾脆全程只用 reset 就好，少一個變數少一個坑，這句提醒比工具本身更重要——會用進階工具不代表該用。

還有第三個指令 `npm run pull`，用來在課程更新時，把上游主分支的新內容拉下來，通常是發現「這個真的不該漏掉」之後的緊急修補才會用到。三個指令背後其實是同一套自製 CLI 在跑，包成 npm script 只是不想讓你去記 git 語法。這堂課表面上是工具教學，實際在解決的是遠距教學最痛的一個問題：老師畫面和學生畫面永遠對不齊，而這套工具鏈，就是把「對齊」這件事變成一行指令。

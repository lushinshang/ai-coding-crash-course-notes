第3章 認識 Claude Code · 3-02

管理 Claude Code session

/usage、/context、/clear 三個指令,決定你什麼時候會沒額度可用、什麼時候該重新開始。
9K → 6.6K
/clear 前後的 context token 用量
137
/clear 後訊息 token 數,基本上是空的
5x
課程建議額度方案(示範時開的是 20x)

啟動 Claude Code 之後,第一件該做的事不是打字下指令,而是輸入 `/terminal-setup` 並按 enter。這一步在設定 shift+enter 這個按鍵組合,少了它,之後想打多行 prompt 就會遇到莫名其妙的換行錯亂。執行完成後輸入框會變成一種淡紫色(lilac),沒變色就代表沒設定成功——這是個小細節,但確實是新手最容易卡關、卻最不會想到回頭檢查的地方。

接下來三個指令,決定了你能不能撐過一整個工作階段而不出狀況。`/usage` 顯示的是這個 session、本週、甚至搭配訂閱方案的額度剩餘量;它的價值不是「現在看一眼」,而是提醒你額度是會見底的——見底之前用完,見底之後就得等重置。這裡藏著一個容易被忽略的判斷:額度等級不是開越高越好,夠用就好,課程建議的方案比示範用的低了整整四級,多數時候根本用不到那麼高的上限。`/context` 則是拆解目前對話裡裝了什麼——system prompt、系統工具、skills、以及這輪對話累積的訊息,各自佔了多少 token,同時告訴你目前模型的 context window 總上限有多大。這個指令現在看起來像個花俏的儀表板,但後面談 context 管理的章節,幾乎每一招省 token 的技巧都要靠它才能驗證有沒有生效。

最後是清空與中斷,這兩件事處理的是完全不同的問題。`/clear` 把整段對話歷史砍掉重來——清空前 context 裡累積了將近 9K token,清空後只剩 137 個訊息 token、整體落回 6.6K 的底噪,這個數字對照具體示範了一件事:模型本身是無狀態的,所謂的「記憶」全部裝在這個會被清空的 context 裡,砍掉就是砍掉,沒有任何東西被悄悄留下。另一種清空方式是連按兩次 Ctrl+C 直接離開再重開一個全新 session,效果相同。至於中斷正在執行的任務,按一次 Escape 就能打斷,對話裡會自動插入一句「interrupted, what should Claude do instead」讓你接著下指示;再按一次 Escape 可以繼續中斷。誤觸也沒關係,大不了打一句「carry on」接回去,不必因為按錯就重開。

第3章 認識 Claude Code · 3-03

在 terminal 下 prompt

@ 引用檔案不花一次請求、Ctrl+S 暫存半成品 prompt、直接貼圖問畫面裡有什麼。

把一份 spec 文件整份塞給 Claude,最直覺的做法是打開檔案、複製全部內容、貼進輸入框。這個做法能動,但多繞了一手——真正省事的方式是打 `@` 之後模糊搜尋檔名,例如 `drizzle.config.ts`、`routes.ts`,按 enter 或 tab 直接拉進輸入框。差別不只是打字量,被 `@` 引用的檔案是直接讀進 context window,不會另外觸發一次工具呼叫,也就是不會多花一次 model provider request——對話還沒開始,那個「先讀檔、再回報讀到什麼」的中間步驟就已經省掉了。

第二個技巧解決的是另一種摩擦:你打了一段還沒想清楚要不要送出的話。按 Ctrl+S 就能把這段文字暫存起來,畫面左下角出現一個小標記,提醒你有東西還在等你。這時候可以先送出別的訊息、插一句補充,等想法整理好了再把暫存內容叫回來繼續編輯。這個功能的價值不在「省一次複製貼上」,而在於它承認一個事實:好的 prompt 常常不是一次打完的,是打了一半、被打斷、回頭補完的——工具願意配合這種節奏,你才不會因為怕漏掉半成品而硬把沒想清楚的句子送出去。

第三個技巧是貼圖:直接複製一張圖片、用 Ctrl+V 貼進輸入框,終端機左下角會顯示貼圖狀態。送出後 Claude 能直接看懂畫面內容回答——連教堂鐘樓的細節都答對了。這提醒你這個輸入框不只是文字通道,遇到 UI 截圖、報錯畫面、設計稿這類東西,直接貼上通常比硬擠出一段文字描述更快也更準。三個技巧合起來其實在講同一件事:輸入介面的熟練度本身就是 prompt 工程的一部分,不是打字之外的附加題。
